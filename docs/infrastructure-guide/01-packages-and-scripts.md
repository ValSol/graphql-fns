## Part 1. Packages, scripts, settings

### Step 1. Packages

```json
{
  "dependencies": {
    "@graphql-tools/merge": "^9.2.4",
    "@graphql-yoga/subscription": "^5.1.0",
    "@swc/core": "^1.16.2",
    "fast-deep-equal": "^3.1.3",
    "graphql": "^17.0.2",
    "graphql-fns": "0.1.2-beta.1169",
    "graphql-yoga": "^5.24.1",
    "mongoose": "^9.10.1",
    "next": "^16.3.7",
    "react": "^19.3.0",
    "react-dom": "^19.3.0",
    "react-relay": "^21.0.1",
    "relay-runtime": "^21.0.1",
    "server-only": "^0.0.1"
  },
  "devDependencies": {
    "@types/node": "^26.6.0",
    "@types/react": "^19.3.0",
    "@types/react-dom": "^19.3.0",
    "relay-compiler": "^21.0.1",
    "tsx": "^4.23.13",
    "typescript": "^5.9.3"
  }
}
```

| Package | Why |
|---|---|
| `graphql-fns` | the library; install the `beta` tag (`yarn add graphql-fns@beta`) and pin the exact version |
| `graphql`, `mongoose`, `@graphql-yoga/subscription`, `@swc/core`, `fast-deep-equal` | peer dependencies of `graphql-fns` (`graphql` 17.x, `mongoose` 9.x) |
| `graphql-yoga` | the GraphQL server |
| `@graphql-tools/merge` | merges the generated and the manually created parts of the schema ([part 2](02-schema.md)) |
| `react-relay`, `relay-runtime`, `relay-compiler` | the GraphQL client and its compiler; version 21 ships its own TypeScript types, `@types/react-relay` is not needed ✅ |
| `server-only` | makes the build fail if a server module gets into a client bundle |
| `tsx` | runs the script that writes `schema.graphql` |

`babel-plugin-relay` is not needed: Next.js compiles the `graphql` tags itself ([part 4](04-relay.md), step 1) ✅.

### Step 2. Scripts

```json
{
  "scripts": {
    "schema": "tsx src/schemaComposer.ts",
    "relay": "mkdir -p src/__generated__ && relay-compiler",
    "dev": "yarn schema && yarn relay && next dev",
    "build": "yarn schema && yarn relay && next build",
    "start": "next start",
    "typecheck": "tsc --noEmit"
  }
}
```

- `yarn schema` writes `src/schema.graphql` from the configs ([part 2](02-schema.md)); `yarn relay` compiles the `graphql` tags of the components against that file into `src/__generated__/` ([part 4](04-relay.md)). The order matters: the compiler reads the file the first script writes.
- `mkdir -p`: `relay-compiler` refuses to start if the artifact directory does not exist (`The artifactDirectory does not exist at ./src/__generated__`) ✅.
- `dev` and `build` generate both outputs first, so a fresh clone works without extra steps ✅.
- While the dev server is running, run `yarn relay` in another terminal after a change of a `graphql` tag, and `yarn schema && yarn relay` after a change of the schema. `relay-compiler --watch` does it automatically, but it needs [watchman](https://facebook.github.io/watchman/) installed (`Cannot run relay in watch mode if watchman is not available`) ✅.

### Step 4. `.env.local` and `.gitignore`

```
# .env.local
MONGODB_URI=mongodb://127.0.0.1:27017/my-app
```

`transactions: true` in the server-side config requires a replica set ([part 11 of the guide to the configs](../configs-guide/11-transactions.md)); everything else works with a standalone MongoDB.

```
# .gitignore
/node_modules
/.next
next-env.d.ts
*.tsbuildinfo
.env*.local

# generated by "yarn schema" and "yarn relay"
src/schema.graphql
src/__generated__
```

Both outputs are reproducible from the sources, so the example keeps them out of Git. Committing `src/schema.graphql` is a reasonable alternative: then a change of the API is visible in a diff.

### Checklist

- [ ] `graphql-fns` pinned to an exact version, its peer dependencies installed;
- [ ] `schema` → `relay` → `next` in both `dev` and `build`;
- [ ] the artifact directory is created before `relay-compiler` runs;
- [ ] `MONGODB_URI` in `.env.local`, generated files in `.gitignore` (or `schema.graphql` committed deliberately).
